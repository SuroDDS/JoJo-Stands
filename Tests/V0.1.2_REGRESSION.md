# v0.1.2 — stability regression checklist

This branch includes a small NPC combat loop optimization and repository cleanup. These changes have **not yet been compiled or tested in-game**.

## Build
- [ ] Build against the installed RimWorld 1.7 game libraries using `build.ps1`
- [ ] No compiler errors or new warnings
- [ ] Startup shows no red errors

## Existing player loop
- [ ] Create arrow via Dev Mode; use it on a colonist
- [ ] Successful awakening grants exactly one Stand
- [ ] Summon, punch and recall work
- [ ] Cooldown is enforced; reload maintains state

## NPC Stand loop
- [ ] Enable NPC stand users in mod settings
- [ ] Test a hostile stand user who reaches a valid target within range
- [ ] Stand attack occurs once, then does not occur during cooldown
- [ ] Once cooldown ends, another attack can occur
- [ ] No exceptions when an NPC is downed or dies, or when target disappears

## Edge cases for upcoming stability work (not fixed by this branch)
- [ ] Failure of arrow: injury or death as configured
- [ ] No second Stand from a second arrow
- [ ] Infant receives latent potential and inherits correctly
- [ ] NPC and animal spawn chances match configured rates across many spawns
- [ ] No noticeable lag during large raids

## Repository
- [ ] `Source/JoJoStand/obj/` is no longer tracked in Git
- [ ] `git status` is clean after an ordinary build, apart from explicitly tracked build output DLL/PDB

## Notes
The NPC optimization skips scanning all targets when the Stand's punch is still on cooldown. It does not change target selection, attack range, damage or cooldown values. Existing gameplay is expected to remain unchanged; confirm in-game before merging.

## Combat diagnostics (new in this branch)
- [ ] Mod settings have a new **Stand combat debug** checkbox, OFF by default
- [ ] With debug OFF, no `[JoJoStands][COMBAT]` messages are generated by punches
- [ ] With debug ON, force a Stand user (pirate or colonist) to attack a valid target at 1–2 tiles
- [ ] A valid punch produces `[JoJoStands][COMBAT][HIT]` in the developer log with tick, owner, target, Stand ID, base damage, range and cooldown
- [ ] A nearby visible Stand hit also produces a labeled in-game notification
- [ ] Try an invalid manual punch (out of range / blocked line of sight / target despawned): `[REJECT]` includes a clear reason
- [ ] A pirate with a gun can still fire normally and punch with its Stand when within range
- [ ] Confirm repeated NPC failures do not spam the log more than once per NPC per 600 ticks
- [ ] Re-open settings after save/load; the debug toggle remains unchanged
- [ ] Russian and English settings/notifications render without missing translation keys

### Interpretation
`baseDamage` is the raw Stand attack's damage value before RimWorld armor/body-part processing; it is not a guaranteed 14-HP health loss.
The visible message/log identifies **Star Platinum** as the attack source for debugging.
**This is not yet a custom entry in RimWorld's native battle log or a new injury-causing DamageDef**: injuries still use vanilla Blunt damage attributed to the Pawn.
